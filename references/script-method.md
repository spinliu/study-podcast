# 学习播客脚本写作方法

把一篇难读的专业论文/文档，改写成一段「深入浅出、双人对话」的播客逐字稿。脚本质量是这个 skill 的内核 —— 音频只是包装。

## 输出格式（机器要求，务必遵守）

- 每句台词独占一行，格式严格为：`**【<说话人名>】** 台词内容`
  - 两个说话人：默认 **小鹿**（女声，好奇的外行，替听众问问题）和 **老唐**（男声，讲透的专家，带判断）。
  - `synthesize.py` 靠这个格式切分，名字必须和传给脚本的 `--female-name / --male-name` 一致。
- 台词里不要放 Markdown 表格、图片、脚注。可以有标题行（`#`、`##`）和引用行（`>`）做分段，它们不会被读出来。
- 全程第一人称口语，像两个人真的在聊天，不是念稿。

## 两种模式（接到任务先问用户要哪种）

- **精炼版**：~2000 字、一条主线讲透核心洞察，10 分钟以内。抓住论文最关键的那一两个点 + 一个主锚比喻 + 带判断 + 落到听众。其余细节舍弃。
- **详细版**：把论文的每个核心模块/特征逐个展开，每个都讲到听懂 + 能举一反三，每个关键专业名词都用一个比喻钉进脑子。时长跟着干货走，不注水。

## 5 条质量标准（精炼/详细都适用）

1. **问题驱动，不是结构驱动。** 别顺着 abstract→方法→结论平铺。先重构问题：作者面对的真问题是什么、旧办法卡在哪、这篇的核心一招是什么。
2. **一个主锚比喻贯穿全篇。** 给整篇找一个听众生活里的类比（如"把身体当一家公司"），全程复用同一个锚，而不是每段一个零散比喻。详细版里，每个子概念再各配一个能"记得住"的小比喻。
3. **带判断地读。** 论文都自卖自夸。明确标出"作者吹的"vs"真站得住的"、前提条件、相关性≠因果、代理指标的陷阱。这是和"摘要型工具"的根本区别。
4. **放大反直觉的那一下。** 找到论文里"等等，居然是这样？"的点，把那个 aha 放大成高潮，而不是平铺。
5. **落到"对听众意味着什么"。** 结合听众的身份（投资/经营/产品/自身），给出可迁移的一招。外部价值收口。

## 写作流程

1. 通读 source 文本，先抓"真问题 + 核心一招 + 最反直觉的点"。
2. 选主锚比喻。
3. 按模式（精炼/详细）和 5 标准写对话。开场用一个钩子（一个具体、反直觉的事实）。
4. 结尾留一句"金句"收口。
5. 落款：`*（解读 by <bot 名> · 基于 <论文出处>）*`。

## 反面清单（别犯）

- 不要复述摘要、不要堆术语、不要"水时长"。
- 不要编造数据/结论；只基于 source。拿不准的标注信心度。
- 不要每段塞一个不相关的比喻；锚要统一。
- 不要省略"带判断"那一段 —— 它是这个 skill 最值钱的部分。
